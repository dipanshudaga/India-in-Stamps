# Product Requirements Document (PRD)
**Project Name:** India in Stamps
**Objective:** To curate a comprehensive, historically accurate, and beautifully digitized collection of Indian postage stamps (1947–Present) and showcase them through a premium iOS application.

---

## 1. Project Overview & Vision
The "India in Stamps" project aims to digitize and preserve the rich philatelic history of India. The project involves scraping, sanitizing, and AI-enriching data for every stamp issued since independence. The culmination of this data effort is a natively built iOS App that acts as an interactive, offline-first historical catalog.

## 2. Current State of Data (The Foundation)
The data gathering, cleaning, and auditing phases are complete. The project relies on the following core assets:

### A. Master Dataset (`Stamps Enriched.csv`)
- **Total Records:** 3,045 fully processed stamps.
- **Data Points:** 
  - Standard metadata: Serial numbers, issue dates, official names, and years.
  - Historical Currencies: Pre-decimal currencies (Annas/Paise) have been mathematically converted into standard decimal INR.
  - AI Enrichment: Every stamp contains a custom 1-2 sentence historical description and semantic categorization tags generated by the Gemini API.

### B. Image Assets (`Stamps Images/`)
- High-quality `.jpg`/`.jpeg` images for nearly every stamp in the dataset.
- Systematically organized into subdirectories by `[Year]` (e.g., `Stamps Images/1947/`).

### C. Data Auditing & Integrity
- The local dataset and filesystem have been meticulously audited against official Wikipedia records (`audit_table.md`).
- The audit successfully reconciled complex miniature sheet layouts (multiple stacked images per denomination) and text-only placeholders on Wikipedia. 
- **Known Gaps:** The audit identified exactly **21** physical images missing from the local filesystem (documented in `missing_main_images.md`).

---

## 3. iOS App Requirements (Next Phase)
With the data architecture finalized, the next phase is building the frontend application. 

### Target Platform
- **Framework:** SwiftUI natively on iOS.
- **Architecture:** Offline-first. The app must parse the local CSV and render local images without relying on network latency.

### Core Features
1. **Timeline Navigation:** Users should be able to browse stamps chronologically by year (1947 to Present).
2. **Gallery View:** A highly visual, grid-based layout displaying the stamp images.
3. **Detail View:** Tapping a stamp should reveal its high-resolution image, denomination, issue date, AI-generated semantic tags, and the deep historical context description.
4. **Search & Filter (Future):** Ability to search by tags, personalities, or historical events based on the enriched CSV data.

### Design Aesthetics
- **Premium Feel:** The UI should feel like a modern digital museum—clean typography, generous whitespace, and subtle micro-animations that respect the historical significance of the subject matter.
